## Boundary

Yazelix owns the packaged Nushell process, layered startup configuration,
runtime `PATH`, and profile state directories. CodeDB owns typed source capture,
compiler/Cargo evidence, blobs, and query semantics. Nushell is the table and
plugin cockpit. Envctl remains an export/materialization consumer rather than a
second CodeDB source-of-truth owner.

## CodeDB placement and registration

CodeDB should be packaged beside Yazelix runtime tools, exposing its CLI and
`nu_plugin_codedb` binary through an explicit runtime package/path contract.
Registration should be runtime-specific:

1. transient `nu --plugins` proof with temporary HOME/XDG state;
2. explicit user `plugin add`/`plugin use` only when the user requests a
   persistent registry entry;
3. a provenance-bearing Yazelix-generated bridge only when a later Yazelix
   package contract defines that materialization.

Host Nu and packaged-runtime Nu versions/protocols must be checked separately.
If plugin compatibility fails, the CodeDB CLI remains available and no tracked
config or real user registry is mutated.
